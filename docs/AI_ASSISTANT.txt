AI ASSISTANT - PRODUCTION IMPLEMENTATION
=========================================

Overview:
---------
The AI Assistant is a production-ready chat interface that helps developers understand and fix security vulnerabilities found in their VettCode scans. It uses Gemma 2 9B via OpenRouter API.

Key Features:
-------------
✅ Real-time chat with AI security expert
✅ Context-aware responses based on scan report
✅ Markdown rendering with syntax highlighting
✅ Code examples for vulnerability fixes
✅ Rate limiting (20 requests/hour per IP)
✅ Request timeout handling (30s)
✅ Graceful error handling
✅ Loading states and user feedback
✅ Quick question suggestions
✅ Conversation history (last 5 messages)
✅ Character limit on input (500 chars)
✅ Abort/cancel ongoing requests
✅ Responsive UI with animations

Architecture:
-------------

1. Components:
   - AIAssistant.tsx - Main chat UI component
   - MessageBubble - Individual message display with markdown
   - LoadingIndicator - Animated loading state

2. Hooks:
   - useAIChat.ts - Manages chat state, API calls, error handling
   - Handles message history, loading states, cancellation

3. API Route:
   - /api/ai-chat - Backend endpoint with production features

4. Libraries Used:
   - react-markdown - Markdown parsing and rendering
   - remark-gfm - GitHub Flavored Markdown support
   - react-syntax-highlighter - Code syntax highlighting
   - framer-motion - Smooth animations
   - react-hot-toast - Error notifications

Production Best Practices:
---------------------------

1. RATE LIMITING
   - 20 requests per hour per IP address
   - In-memory rate limit store (use Redis in production scale)
   - Returns 429 status with reset time when exceeded
   - Headers: X-RateLimit-Limit, X-RateLimit-Remaining, X-RateLimit-Reset

2. INPUT VALIDATION
   - Message length validation (max 500 chars in UI, 1000 in API)
   - Type checking for all inputs
   - Sanitization of user inputs
   - Validation of report data structure

3. ERROR HANDLING
   - Try-catch blocks around all async operations
   - Graceful fallback messages on API failures
   - Request timeout (30s) with AbortController
   - Network error detection and user-friendly messages
   - Development vs production error messages

4. SECURITY
   - Rate limiting prevents abuse
   - Input validation prevents injection attacks
   - API key stored in environment variables
   - XSS prevention in markdown rendering
   - Sanitization of HTML output
   - CORS headers properly configured

5. PERFORMANCE
   - Request cancellation support
   - Conversation history limited to 5 messages (token optimization)
   - Memoization of components (React.memo)
   - useCallback for event handlers
   - Smooth scroll behavior
   - Lazy rendering of markdown

6. USER EXPERIENCE
   - Loading indicators during API calls
   - Error toasts for failures
   - Quick question suggestions for first-time users
   - Character counter on input
   - Keyboard shortcuts (Enter to send, Shift+Enter for newline)
   - Auto-scroll to latest message
   - Cancel button during loading
   - Responsive design
   - Smooth animations

7. CODE QUALITY
   - TypeScript for type safety
   - Proper error types and interfaces
   - Separation of concerns (hooks, components, API)
   - Reusable utility functions
   - Clean component structure
   - Proper naming conventions
   - Comments where needed

API Configuration:
------------------

Environment Variables Required:
- OPENROUTER_API_KEY: Your OpenRouter API key
- NEXT_PUBLIC_SITE_URL: Your site URL for attribution

Model Configuration:
- Model: google/gemma-2-9b-it:free
- Temperature: 0.7 (balanced creativity/accuracy)
- Max Tokens: 1500
- Top P: 0.9

System Prompt Strategy:
-----------------------
The AI is given:
1. Report context (score, grade, severity counts)
2. Top 15 priority issues with details
3. Guidelines for communication style
4. Instructions to provide actionable advice
5. Code examples when relevant

Conversation history (last 5 messages) is included for context while keeping token usage reasonable.

Rate Limiting Details:
----------------------
- Window: 1 hour (3600 seconds)
- Max requests: 20 per IP
- Implementation: In-memory Map (production should use Redis)
- Cleanup: Automatic cleanup every hour
- Response headers include rate limit info

Error Scenarios Handled:
------------------------
1. API key not configured → User-friendly message
2. Rate limit exceeded → 429 status with reset time
3. Request timeout (30s) → Prompt to ask more specific question
4. OpenRouter API error → Fallback message
5. Network errors → Connection error message
6. Validation errors → 400 status with specific error
7. Unexpected errors → Generic error message (detailed in dev mode)
